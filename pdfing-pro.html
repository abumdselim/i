The problem

PDF is where documents become someone else’s problem.

Merge this, split that, remove the page numbers, add a stamp, compress it under ten megabytes, turn the scan back into text. The work is small, repetitive and usually urgent.

Free web tools solve it by uploading the file to an unknown server. Desktop tools solve it by installing something you cannot audit. Neither is acceptable when the document is a contract.

Capability

What it does.

Six parts of the product that do the daily work. Everything else supports these.

Organise and assemble

Merge, split, reorder, rotate, crop, n-up, booklet, and page numbering across a hundred files.

Convert in both directions

Word, Excel, PowerPoint, HTML, Markdown, images and scans, in and out of PDF.

Security work

Encrypt, decrypt, redact, sanitise, flatten and strip metadata before a file leaves the building.

OCR and extraction

Text from scans, tables to CSV, images out of pages, attachments out of containers.

Sign and verify

Digital signatures, signature checks and form filling without a printout.

Batch and repeat

Chain tools into a workflow and run it across a folder instead of one file at a time.

Engineering

How it is built.

Three decisions that shape the product, and the stack that carries them.

D/01

Server-side on purpose

Heavy work happens where it can be sandboxed, rate-limited and logged, not in a tab that may close halfway.

D/02

Nothing is kept longer than the task

Files are processed per request, and the workspace is temporary by design.

D/03

Works without a network too

The same build ships as a desktop application and a PWA for documents that cannot leave the machine.

Stack

Next.jspdf-libpdf.jsTesseractElectronCloudflare

One codebase produces the web app, the installable PWA and the desktop build. The heavy libraries are shared, so a fix lands everywhere at once.
