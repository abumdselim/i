## 1. লক্ষ্য — ৩০ সেকেন্ডে

মালিক চান সাইটের **প্রতিটা পেজ, প্রতিটা সেকশন** একটা অত্যন্ত প্রফেশনাল, সব ডিভাইসে রেস্পন্সিভ
অ্যাডমিন প্যানেল থেকে এডিট, হাইড ও কন্ট্রোল করতে — এমনভাবে যেনে **ভবিষ্যতে প্রতিটা নতুন সেকশন
যোগ হলে তার কন্ট্রোলও অ্যাডমিনে একই সাথে চলে আসে।**

কী তৈরি হবে: **Intactic Studio** — সাইটের সোর্স কনটেন্ট পড়া/লেখা, সেকশন শো-হাইড-রিঅর্ডার,
নেভিগেশন/ফুটার এডিটিং, বিল্ড-ভেরিফাই চালানো আর লাইভ প্রিভিউ — সব এক প্যানেলে।

## 2. স্থাপত্য-সিদ্ধান্ত — কেন "লোকাল স্টুডিও"

সাইটটা `output: 'export'` — বিল্ডের আউটপুট শুধু স্ট্যাটিক ফাইল (D-01 → D-13)। রানটাইমে কোনো সার্ভার,
ডেটাবেজ বা সেশন নেই। "সবকিছু অ্যাডমিন থেকে কন্ট্রোল" মানে দুটো পথ ছিল:

| | পথ A: রানটাইম CMS | পথ B: বিল্ড-টাইম কন্ট্রোল (নির্বাচিত) |
|---|---|---|
| কী | WordPress/Strapi/হেডলেস CMS, সাইট সার্ভার-রেন্ডার্ড | অ্যাডমিন সোর্স কনটেন্ট লেখে → বিল্ড → ডিপ্লয় |
| হোস্টিং | পাল্টাতে হয়, খরচ ও জটিলতা বাড়ে | অপরিবর্তিত — যেকোনো স্ট্যাটিক হোস্ট |
| D-13-এর সাথে | সরাসরি সাংঘর্ষিক | সম্পূর্ণ সঙ্গতিপূর্ণ |
| নিরাপত্তা-সারফেস | CMS, লগইন, প্লাগইন-আপডেট | শূন্য (লোকালহোস্ট-অনলি) |
| ইতিহাস | CMS-এর ভেতরে | git-এ — প্রতিটা বদল একটা কমিট |
| অফলাইনে কাজ | না | হ্যাঁ |

**সিদ্ধান্ত:** পথ B। অ্যাডমিন প্যানেল একটা **লোকাল স্টুডিও** — রিপোজিটরির উপরে প্রফেশনাল UI।
মালিকের ওয়ার্কফ্লো: **এডিট → সেভ (সোর্সে লেখে) → বিল্ড (বাটন, লাইভ আউটপুটসহ) → প্রিভিউ (এমবেডেড)
→ ডিপ্লয় (হোস্ট ঠিক হলে)**।

**"নতুন সেকশন = নতুন কন্ট্রোল" যেভাবে কাজ করবে:** সাইটের প্রতিটা সেকশন একটা সিঙ্গেল
**সেকশন রেজিস্ট্রি**-তে (`src/lib/sections.ts`, পিওর ডেটা) নিবন্ধিত থাকবে; অ্যাডমিন UI এই রেজিস্ট্রি
থেকেই নিজে নিজে পেজ-বাই-পেজ সেকশন লিস্ট বানাবে। কোডে নতুন সেকশন যোগ করলে রেজিস্ট্রিতে এন্ট্রি
দিলেই অ্যাডমিনে হাইড/অর্ডার কন্ট্রোলসহ দেখা যাবে — আলাদা অ্যাডমিন-কোড লেখা লাগবে না।

**স্কেল-আউট পথ:** স্টুডিও কখনো LAN/অনলাইনে গেলে শুধু রাইট-API-এর পেছনের স্তর (ফাইল → সার্ভিস) ও
auth বদলালেই হবে; UI, ফর্ম-সিস্টেম, বিল্ড-প্যানেল অপরিবর্তিত থাকবে।

## 4. স্থাপত্য ও ফাইল ম্যাপ

```
D:\The Intactic Atelier
├─ next-app/                        ← সাইট (স্থাপত্য অপরিবর্তিত: output:'export')
│   ├─ data/
│   │   ├─ capabilities.json        ← নতুন: মেশিন-লেখ্য কনটেন্ট ডেটা
│   │   ├─ products.json
│   │   ├─ figures.json
│   │   ├─ pages.json
│   │   └─ site-config.json         ← নতুন: সেকশন hide/order ওভাররাইড + nav + footer
│   ├─ src/lib/content/
│   │   ├─ loader.ts                ← নতুন: JSON পড়ে + স্কিমা-ভ্যালিডেট করে এক্সপোর্ট দেয়
│   │   └─ schema.ts                ← নতুন: রানটাইম ভ্যালিডেটর (types.ts-এর সাথে মিলবদ্ধ)
│   ├─ src/lib/sections.ts          ← নতুন: সেকশন রেজিস্ট্রি (পিওর ডেটা)
│   └─ scripts/manifest.mjs         ← অপরিবর্তিত (loader থেকেই PAGES পায়)
└─ admin-app/                       ← নতুন: Intactic Studio
    ├─ package.json                 ← scripts: dev (3001) · build · lint · typecheck
    ├─ src/app/
    │   ├─ layout.tsx · page.tsx    ← শেল + ড্যাশবোর্ড
    │   ├─ pages/[route]/           ← পেজ ডিটেইল: মেটা + সেকশন ম্যানেজার
    │   ├─ navigation/ · footer/    ← গ্লোবাল এডিটর
    │   ├─ content/[type]/[slug]/   ← ক্যাপাবিলিটি/প্রোডাক্ট এডিটর
    │   ├─ build/                   ← বিল্ড প্যানেল
    │   └─ api/                     ← read/write কনটেন্ট · build · preview (localhost-only)
    └─ src/lib/
        ├─ site.ts                  ← সাইটের data/ ফোল্ডার পড়া/লেখার একমাত্র পথ (ভ্যালিডেশনসহ)
        ├─ fields.ts                ← ফিল্ড-ডেসক্রিপ্টর সিস্টেম (সব এডিটরের ভিত্তি)
        └─ sections.ts              ← সাইটের রেজিস্ট্রির টাইপ-শেয়ার (relative import)
```

**পাঁচটা লোড-বেয়ারিং নীতি:**

1. **সাইটের বিল্ড-আর্টিফ্যাক্ট পবিত্র** — `admin-app/` কখনো `next-app/out/`-এ প্রবেশ করবে না; সাইটের
   `next.config.ts`, রুট, কম্পোনেন্ট-স্ট্রাকচার অপরিবর্তিত। ফেজ A-র শেষে সাইটের একমাত্র বদল:
   কনটেন্ট-সোর্স TS লিটারেল → JSON + loader, সেকশন রেজিস্ট্রি + কন্ডিশনাল রেন্ডার।
2. **মডিউল-চুক্তি অপরিবর্তিত** — `CAPABILITIES`, `PRODUCTS`, `FIGURES`, `PAGES` একই নামে, একই ফাইল থেকে
   এক্সপোর্ট হবে; কোনো কনজিউমার (কম্পোনেন্ট, `manifest.mjs`, gate) বদলাবে না। ফলে ফেজ ১ প্রমাণযোগ্যভাবে
   শূন্য-ড্রিফট।
3. **সেকশন রেজিস্ট্রি = একমাত্র সত্য** — অ্যাডমিন সেকশন-লিস্ট নিজে বানাবে না, রেজিস্ট্রি থেকে পড়বে;
   সাইট রেন্ডারও রেজিস্ট্রি + `site-config.json` থেকে সিদ্ধান্ত নেবে। দুই দিক এক সোর্স দেখে।
4. **সব রাইট ভ্যালিডেটেড + অ্যাটমিক** — অ্যাডমিন যা লেখে, লেখার আগে স্কিমা-ভ্যালিডেশন, লেখে টেম্প ফাইলে
   তারপর অ্যাটমিক রিনেম-কপি করে; ভাঙা JSON কখনো সোর্সে বসবে না। প্রতিটা সেভের আগে ব্যাকআপ
   `.bak` (দ্রুত রোলব্যাকের জন্য)।
5. **স্টুডিও localhost-only** — dev সার্ভার `127.0.0.1:3001`; কোনো auth নেই কারণ বাইরে থেকে পৌঁছানোর
   কথাই নয়। অনলাইনে যাওয়ার দিনটাই auth বসবে (ফেজ C)।

  scroll-lock, Escape-বন্ধ, ফোকাস-ম্যানেজমেন্ট); এডিটরের অ্যাকশন-বার নিচে স্টিকি।

  নেভিগেশন, `prefers-reduced-motion` সম্মান।

## 9. নিয়ম — স্পর্শযোগ্য বনাম অস্পৃশ্য

| স্পর্শযোগ্য | কখনোই নয় |
|---|---|
| `next-app/src/lib/content/*` (লোডার-রূপান্তর), `next-app/data/*` | `qa/reference/**` — ফ্রোজেন বেসলাইন (approve.py ছাড়া) |
| `next-app/src/lib/sections.ts`, ১৯ রুটের রেন্ডারিং | রুট `*.html`, `sitemap.xml`, `robots.txt` — legacy artefact |
| `admin-app/**` | সাইটের `next.config.ts`, `globals.css`, `icons.ts` (ফেজ A-তে) |
| `docs/*` | `legacy/**` |

**গার্ডরেল:** প্রতিটা ফেজ = এক কমিট, সার্জিকাল `git add` (বর্তমান আনকমিটেড D-14 কাজ আমাদের
কমিটে জড়াবে না); গেট সবুজ ছাড়া কোনো ফেজ শেষ নয়; সাইট-কপি ইচ্ছাকৃত বদল হলে অবশ্যই গেটে ধরা
পড়বে — সেটাই নকশা, approve যতক্ষণ না ফেজ B বাটন হয় `scripts/approve.py` হাতে।
